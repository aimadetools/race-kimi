What an agent-powered migration review looks like

Drop the MCP server into your agent's config and ask it to review a migration PR.

You
Review this PR's schema change. Old schema is in migrations/001_initial.sql, new schema is in migrations/002_add_orders.sql. Tell me if it's safe to deploy.
Agent · calling schemalens_diff_schemas
I'll compare the two schemas and check for breaking changes.
Agent · result
Summary: 1 table added (orders), 1 column added (users.email_verified_at), 1 index added.

Risk score: 2/10 — Low risk.
No dropped columns, no type changes, no removed constraints. The new orders table references users(id) with a foreign key and ON DELETE SET NULL, which is safe. Recommend adding the migration during a low-traffic window.
You
Generate the PostgreSQL migration and rollback SQL.
Agent · calling schemalens_generate_migration
Done. Here is the forward migration and the rollback script in case you need to revert.

Agent workflow

Plug SchemaLens into any agentic pipeline in four steps.

1

Detect schema change

Agent reads the PR, branch diff, or migration file and identifies that a schema changed.

2

Call SchemaLens MCP

Agent invokes schemalens_diff_schemas with the old and new CREATE TABLE dumps.

3

Analyze risk

Agent uses schemalens_detect_breaking_changes to surface high, medium, and low severity issues.

4

Post review

Agent comments on the PR, Slack, or ticket with the diff summary, risk score, and migration SQL.

1

Install the MCP server

Clone the repo or download mcp-server.js. Use the config generator to build the exact JSON for your agent's client.

git clone https://github.com/aimadetools/race-kimi.git cd race-kimi # Generate the exact MCP config for your agent's client: open https://schemalens.tech/tools/mcp-config-generator.html
2

Choose a prompt pattern

Use these prompts to guide your agent toward useful schema review behavior.

PR Review: "Review the schema changes in this PR. Compare the old and new schemas, list breaking changes, and give a deploy recommendation (safe / risky / blocking)."
Migration Author: "Generate the migration SQL to go from schema A to schema B in [dialect]. Include a rollback script and flag any operations that could lock large tables."
Drift Detective: "Compare the production schema dump to the schema in this branch. Highlight any drift that isn't reflected in the migration files."
3
