Forward Migration (PostgreSQL)
-- 1. Add new columns
ALTER TABLE users ADD COLUMN phone VARCHAR(20);
ALTER TABLE users ADD COLUMN preferences JSONB DEFAULT '{}';

-- 2. Modify existing columns
ALTER TABLE users ALTER COLUMN email TYPE VARCHAR(255);
ALTER TABLE users ALTER COLUMN email SET NOT NULL;

-- ⚠️ BREAKING: Dropped column referenced by view "user_profiles"
ALTER TABLE users DROP COLUMN legacy_id;

-- 3. Add constraints
ALTER TABLE users ADD CONSTRAINT users_email_unique UNIQUE (email);

-- 4. Create index (safe: online creation)
CREATE INDEX CONCURRENTLY idx_users_phone ON users(phone);

-- 5. New table
CREATE TABLE audit_logs (
  id SERIAL PRIMARY KEY,
  table_name VARCHAR(100) NOT NULL,
  changed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
Rollback Migration (safety net)
-- Reverse all changes if deployment fails
ALTER TABLE users ADD COLUMN legacy_id VARCHAR(50);
ALTER TABLE users DROP COLUMN phone;
ALTER TABLE users DROP COLUMN preferences;
ALTER TABLE users ALTER COLUMN email TYPE VARCHAR(128);
ALTER TABLE users ALTER COLUMN email DROP NOT NULL;
ALTER TABLE users DROP CONSTRAINT users_email_unique;
DROP INDEX idx_users_phone;
DROP TABLE audit_logs;

🔧 How SchemaLens Works

Not a text diff. A semantic engine that understands SQL.

🔧
Custom SQL Parser

~400 lines of vanilla JavaScript, zero dependencies. Parses CREATE TABLE, INDEX, VIEW, TRIGGER, and FUNCTION into structured objects.

🧠
Semantic Diff

Compares tables, columns, indexes, and constraints structurally. Whitespace changes are ignored. Type changes (e.g. VARCHAR → TEXT) are detected precisely.

🔒
Privacy-First

Everything runs in your browser. Your schema dumps never touch our servers. We cannot see your data even if we wanted to.

🖥️
CLI Available

The same engine runs locally via npm. No browser required. npx schemalens-cli diff old.sql new.sql
